# 1.19.1, the patch after 1.19.0 — file 1 of 2: the engine and the pages

This file is self-contained. File 2 (`docs/plans/025-patch-1-19-1-02.md`) holds the content and eval units and the
one unit that writes the specs and the changelog for both files. Every `file:line` resolves at `091d999b`.

## Context

1.19.0 left sixteen deferred rows scheduled to a 1.19.x patch; two more come due with them. This file fixes the ones
in the engine and on the hand-written pages: a misspelt findings fence that reads as clean, operating-system files
that stop a clean run's empty ledger, the land job leaving its issue open, machine paths in land's clean-up output,
an uncapped link-following reader the unattended pre-flight reaches, a legacy-only repository read as fresh, a linked
folder that skips the lane's credential scan, a copied helper, two missing `learn capture` flags, and three undated
or missing sentences on `SECURITY.md` and `docs/factory.md`. Decided at the session's start, on the maintainer's
word: the land job's token gets `issues: write` for that one job, reviewed by the security lens. Out of scope:
every other inbox row on these files (each keeps its own trigger), and any redesign.

## Decisions

- **Run and land is one lane, in sequence** (`a1` → `a2` → `a3`): the three units share
  `test/cli/commands/runLand.test.ts`. `b1`, `b2` and `b3` each have a lane of their own. `p1` follows `a2`, whose
  work its pages state.
- **No lane writes a spec file or `CHANGELOG.md`.** File 2's `z1-truth` writes them once, after every unit.
- **No lane writes a generated client copy, `.stamity/manifest.json` or a golden snapshot.** File 2's
  `y1-regenerate` writes them once, on the integrated branch, so those files have one writer.
- **`learn capture`'s two flags need two words in the guard's option list** (`src/hooks/personOnly.ts:3358`), or
  `test/hooks/personOnly.test.ts:3702-3714` goes red and a proposal line carrying a new flag is held. The research
  returned this as a scope choice; taken by default with nobody watching: the two words are in `b3`, with the
  security lens. The other choice was to drop the flags from the patch.
- **`docs/factory.md:168-169` is reworded, not only dated.** GitHub's REST reference, read on 2026-11-10, gives
  `current_user_can_bypass` no description, so a read date on today's sentence would date a claim the page does not
  make. Taken by default; the other choice was the date alone.
- **A linked source is decided with `stat`, not refused:** refusing would break the pinned linked `node_modules`
  cases (`test/worktree/engine.test.ts:1870`, `:1890`).
