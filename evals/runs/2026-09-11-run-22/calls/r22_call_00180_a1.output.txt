**Do sessions accumulate without bound?**

- Sessions are written into a `Map` held in module scope (`src/session/store.ts:23`) — **high**.
- No eviction call appears anywhere in that file (`src/session/store.ts:57`) — **high**.
- Exactly one store instance is constructed per process (`src/server/boot.ts:31`) — **high**.
- Session entries accumulate for the lifetime of the process (`src/session/store.ts:23`, `src/session/store.ts:57`, `src/server/boot.ts:31`) — **medium**, on the unverified assumption that no module outside `src/session/store.ts` holds a reference to that `Map` and deletes from it, since only these two files were read.

No claim. No test, benchmark, or production measurement of session memory growth exists in the repository, so there is no cited basis for a magnitude, a rate, or a production impact, and the citation rule deletes such a claim rather than hedging it.
