## Unit `json-flag-render`

**`interfaces`**

Flag declaration on the `status` verb:

```
--json    boolean, default false, no value argument, no short alias
```

Emitted object — exactly one, to stdout, on `status --json`:

```ts
export interface StatusJson {
  workspace: string;     // absolute path of the workspace root
  branch: string;        // current branch name
  managedFiles: number;  // integer, count of files under management
  driftedFiles: number;  // integer, count of managed files showing drift
  lastSync: string;      // ISO-8601 UTC timestamp of the last sync
}
```

Exit and stream contract:

- clean run → stdout carries one `StatusJson` object, stderr empty, exit code `0`
- drift finding → stdout carries one `StatusJson` object with `driftedFiles > 0`, exit code `1`
- `--json` absent → existing human-readable rendering and existing exit codes, unchanged
- no key beyond the five; no trailing prose, banner, or second object on stdout

**`testCriteria`**

- `status --json` on a clean workspace writes stdout that `JSON.parse` accepts as a single object whose key set is exactly `{workspace, branch, managedFiles, driftedFiles, lastSync}`
- `workspace`, `branch`, `lastSync` are `typeof === "string"`; `managedFiles` and `driftedFiles` satisfy `Number.isInteger`
- clean workspace → exit code `0`
- workspace with at least one drifted file → exit code `1`, and stdout still parses to a full `StatusJson` with `driftedFiles > 0`
- on the clean run, stderr is the empty string
- invoked without `--json`, the command produces the pre-existing human-readable output and its pre-existing exit code
- `--json` consumes no following token: `status --json extra` leaves `extra` to positional parsing rather than binding it to the flag

**`edgeCases`**

- *Drift present.* The non-zero exit is the only drift signal; the JSON object is still written to stdout in full and stderr stays empty. A consumer that pipes stdout gets valid JSON on both exit paths.
- *Workspace never synced.* `lastSync` is typed `string` by `REQ-cli-140` with no null case, so emit the empty string `""` and never `null` or an absent key — the key set stays fixed at five.
- *`--json` passed twice.* Idempotent: one object, exit code as for a single `--json`.
