## Findings

**1. Injection — `src/api/invoices.ts`, `GET /invoices/:id`**

`req.params.id` is interpolated into the SQL string passed to `db.raw`. A caller sends `' OR '1'='1` and reads every invoice; `'; DROP TABLE` and UNION-based extraction are equally available. The path parameter also never parses into a declared shape (no type, no length bound), so nothing upstream constrains it.

Fix: bound parameter, and parse `id` into its declared shape (e.g. uuid or bounded integer) before it reaches the query.

**2. Broken access control — `src/api/invoices.ts`, `GET /invoices/:id`**

`requireSession` establishes *who* the caller is and nothing more. The handler loads the row addressed by the path and returns it with no check that `req.user` may see that invoice. The identifier is an argument, not a grant: any authenticated caller enumerates every invoice the route can reach.

Fix: load the record and check this caller's permission on *that record*, server-side, on every request.

**3. Broken access control, insecure design — `src/api/invoices.ts`, `POST /invoices/:id/void`**

Same missing per-resource check, on a state-changing action: any session can void any customer's invoice. Additionally `invoices.byId` has no miss branch — when the id matches nothing, whatever it returns (null/undefined) is handed straight to `invoices.void`, so behaviour on the absent case is decided by a function that wasn't asked the question. That path must deny, not proceed.

Fix: authorize against the loaded invoice; return 404/403 when absent; treat an error inside the check as a denial.

**4. Security misconfiguration, authentication failure — `src/config/flags.ts`, `allowTestLogin`**

`process.env.NODE_ENV !== "production"` is the inverted form. Test login turns **on** in every environment nobody named: a fresh container with `NODE_ENV` unset, a renamed stage, `"Production"`, `"prod"`, a typo. An authentication bypass is one misspelled env var from being live.

Fix: allowlist named environments (`allowTestLogin = env === "local" || env === "ci"`), and refuse to boot when the environment value is outside that enum.

**5. Security misconfiguration, insecure design — `src/config/flags.ts`, `seedRoutesEnabled`**

`process.env.SEED_ROUTES !== "off"` fails open: unset enables seed routes, and so does `"OFF"`, `"false"`, `"0"`, or any typo. Seed and reset commands are exactly the capability that must not reach production, and the default here is on.

Fix: gate on the same named-environment allowlist as above; if an explicit variable stays, require an affirmative parsed value and deny on anything unrecognized.

## Secondary

**Insecure design — `SELECT *` in `GET /invoices/:id`**, whose result is passed directly to `res.json`. The response is a trust boundary too; `*` ships whatever columns the schema grows later — internal notes, gateway tokens, soft-delete flags — without a review. Project the named fields the API declares.
