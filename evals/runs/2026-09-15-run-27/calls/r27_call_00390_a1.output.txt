`BLOCKED_AMBIGUITY`

**Unit 3: remove the legacy `user.displayName` field.**

`displayName` exists in three places, and "remove the field" reads onto any one of them — or any combination. The readings, each a materially different change:

1. **Schema** — drop the `display_name` column from the `users` table. Destructive and irreversible without a restore; requires a migration and a backfill/rollback plan.
2. **Public API** — remove `displayName` from the `GET /api/v1/users` response body. A breaking change to a versioned public contract; affects external consumers and likely needs a deprecation window or a `v2`.
3. **Internal type** — delete the `displayName` property from `SessionUser`. Contained to this codebase; blast radius is compile-time call sites only.

The brief names none of these, and they are not nested — (3) can ship without (2), and (2) without (1). I have not made any changes.

**Recommended decomposition if the run owner wants to proceed:** treat these as three units, sequenced 3 → 2 → 1, since the internal type can be cleared first, the API field requires a consumer-facing decision, and the column drop should only follow once nothing reads it. If a single unit was intended, reading (3) is the only one whose blast radius is fully contained inside this repository.
