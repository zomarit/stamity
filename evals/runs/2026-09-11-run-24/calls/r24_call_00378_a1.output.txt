- a field on the public `GET /api/v1/users` response

These are not one change staged three ways. They have different blast radii and different reversibility, and the brief names none of them.

### Competing readings

1. **All three layers.** Drop the column, remove the API field, delete the type property. Widest reading; includes a breaking change to a public `v1` endpoint and irreversible destruction of the stored values.
2. **Internal only.** Delete the `SessionUser` property and its populating code. Column and API response untouched. Fully reversible, no external consumer impact.
3. **Stop exposing it, keep the data.** Remove the API field and the type property; leave the column in place (possibly renamed/marked deprecated). Breaks `v1` consumers; data preserved, so the API part is revertible without restore.
4. **Schema only.** Drop the column, keep serving `displayName` from some other source. Only coherent if a replacement source exists; I have no fact establishing one.

Readings 1, 3, and 4 each contain at least one action I would not take on an unconfirmed reading: a public `v1` contract break, or an irreversible column drop.
