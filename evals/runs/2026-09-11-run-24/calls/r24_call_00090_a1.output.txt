**Surfaces examined:** authentication and session handling, object-level authorization, route registration and resource-consumption controls on the added export path. Cryptography and the dependency set were not touched by this change set.

### Findings

**1 — `Critical` — Broken object-level authorization on export retrieval**
`src/api/exports.ts:34`
The handler resolves the export record from `req.params.id` and streams it after verifying only that a session exists. No predicate ties the authenticated caller to the resolved record, so any session holder can read any export by substituting an id. OWASP **A01:2021 Broken Access Control** / **API1:2023 Broken Object Level Authorization**.
Remediation for the fixer: scope the lookup by owner (query on both id and the session subject) rather than fetching then checking, and return the same not-found response for absent and unauthorized records so the endpoint does not confirm id existence.

**2 — `Warning` — Route registered with no rate limit**
`src/api/exports.ts:12`
The export route is registered without a rate limiter. Exports are a streaming, likely expensive read; unbounded request rate permits resource exhaustion, and combined with finding 1 it permits cheap enumeration of the id space. OWASP **A04:2021 Insecure Design** / **API4:2023 Unrestricted Resource Consumption**.
Remediation for the fixer: apply the project's existing limiter middleware at registration, keyed per session subject rather than per IP.
