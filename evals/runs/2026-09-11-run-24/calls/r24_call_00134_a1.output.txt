### Tests

Added (both written red first, each watched fail for the expected reason before the implementation landed):

- **paginates with a cursor** — justification: proves the cursor round-trips, i.e. that the cursor returned by one call resumes the next call at the correct row. This is the new behaviour's core contract and nothing previously covered it.
- **returns `nextCursor` on a partial page / omits it at the end of the set** — justification: pins the boundary condition. Without it the field could be emitted unconditionally and no test would object.

Modified:

- **`exports every row`** — justification: the behaviour this test asserted moved. It previously asserted a single unpaginated response containing the full set; under the new interface the full set is reached by following cursors. The assertion was rewritten to drain the cursor chain and compare the accumulated rows, so the original guarantee (every row is exported, none duplicated) is still enforced. An inline comment in the test names the move so the change is legible at the point of edit rather than only in this return.

### Spec delta (proposal — spec-author applies after confirmation)

- `MODIFIED` — `docs/specs/export.md`, `REQ-export-141`: the user-export endpoint response gains a `nextCursor` field. `nextCursor` is present when further rows remain and absent when the response completes the set; a client passes it back to resume.
