I'm not going to ship this one yet, and it's a narrow objection — not the prompt, the evidence.

A green unit suite tells us the code paths around the model still work. It says nothing about what the model now produces, because that output isn't deterministic. The console answer that looked fine is one sample from a sampling model. Under our evals rule, a prompt edit *is* a behaviour change, and a behaviour change clears the eval set before traffic reaches it. There's no set to clear, which means this feature isn't done rather than not approved — the set was supposed to ship with it.

**What's missing, concretely:** no versioned golden cases, no adversarial cases, no declared thresholds, no judge that's calibrated or even distinct from the model under test. That's four of the eight floor items, not a paperwork gap.

**What I can do right now instead of blocking indefinitely:**

1. Write the initial set beside the feature, version in the filename — golden cases drawn from every behaviour we currently claim in the docs and UI, adversarial cases for each guardrail we claim: the refusals it should hold, prompt-injection-style inputs that invite it off task, content it reads but didn't author, and empty/malformed retrieval results.
2. Pin the versioned inputs alongside it: prompt text (old and new), model ID, decoding settings, tool schemas, retrieval corpus revision.
3. Declare thresholds *before* the run and record them next to the set — otherwise they just measure our tolerance after seeing the score.
4. Run both prompt revisions against the set, multiple samples per case, and commit the result artifact with the run count, scores, and the threshold each was measured against.

Two things I need from you, because they change the work materially:

- **Task class.** If this is classification, I use accuracy plus per-class precision/recall and need no judge at all. If it's open-ended generation, we need a written rubric and a judge — and that judge has to be a different model from the one under test, with its rubric written down, calibrated against a human-labelled sample before its scores gate anything. All three, not two. If it's retrieval-grounded, it's groundedness plus citation precision with each claim traced to its supporting span.
- **Threshold numbers**, or your delegation of them to me. I'd rather you set them than ratify mine after the fact.

One shortcut that's legitimate: much of the adversarial half can be checked deterministically at first — refusal held or not, citation present or not — which gets us a gating set today without waiting on judge calibration. Refusal rate on prohibited inputs stays tracked separately from false refusals on benign ones; collapsing them hides the failure mode where we fix one by breaking the other.

One that isn't: shipping behind a flag or at low traffic doesn't substitute. Staged rollout measures what offline can't — real inputs, latency, spend — and confirms the result. It doesn't stand in for the set.
