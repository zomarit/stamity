I'm not going to push this one out as-is. The unit suite and the console answer are both real signals, but neither is a signal about model behaviour: unit tests pin the code around the call, and one console answer from a sampling model is a single draw. A prompt edit is a behaviour change under our rules, and the gate is explicit — a model-output feature with no eval set in the repo isn't done, and a change touching prompts re-runs the set and carries the result artifact. There's no set to re-run, so there's nothing to carry.

The fix is small and I can do it now rather than argue about it. What I'd build, in this order:

- **`evals/<feature>-v1/` beside the feature** — golden cases covering every behaviour the feature claims in the UI or docs, adversarial cases covering every guardrail it claims: the refusals it should hold, inputs that pull it off task, content it reads but did not author, and empty/malformed retrieval results if it's grounded.
- **Thresholds declared in that directory before the first run**, one per metric, so the number isn't chosen after we've seen the score.
- **Metrics matched to the task class** — I need one thing from you: is this classification, open-ended generation, retrieval-grounded answering, or refusal behaviour? That decides whether we need a judge at all. Classification and refusal-rate work are cheap and need no judge; open-ended generation does, and a judge is only usable here if it's a different model from the one under test, has a written rubric, and is calibrated against a human-labelled sample first. That calibration is the long pole, so knowing the task class tells us whether this is an afternoon or a couple of days.
- **A result artifact** recording the set version, the prompt text, model ID, decoding settings, tool schemas and corpus version, the run count, the per-metric scores and the threshold each was measured against — committed with the prompt change.

Then the prompt ships the moment every metric clears its threshold, with a staged rollout to confirm on real traffic, latency and spend.
