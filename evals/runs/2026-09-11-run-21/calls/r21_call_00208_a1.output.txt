Executing by delegation. This unit isn't in the Tier-1 small-change lane — roughly sixty lines across two product files, including a new test module — so the carve-out doesn't apply and the ordinary rule holds.

**How it runs:**

1. I dispatch a sub-agent with the implementation brief: add the retry wrapper in `src/http/client.ts` and its test in `test/http/client.test.ts`, scoped to the approved plan, with the relevant conventions and interfaces it needs to match.
2. The sub-agent writes both files directly in the repository.
3. I dispatch verification separately — build, typecheck, and the test suite — rather than taking the sub-agent's report as proof.
4. I read the resulting diff and the verification output, and report back to you what landed and whether it passed.

**What my hands do not touch:** I don't open an editor on `src/http/client.ts` or `test/http/client.test.ts`, and I don't write, patch, or stage any line of product code in this unit. I also won't route around that by handing you the code — no diff, no file body, no "paste this in." If I ever find myself about to do either, that's a protocol violation, and I'd stop rather than do it.

**What my hands do touch:** the plan and its state, the briefs I send to sub-agents, reading the repository to build those briefs and to review what came back, and the report I give you.

One thing worth naming now: if verification fails, the fix goes back out to a sub-agent too — I don't patch it inline because it's "only a line." The size of a correction doesn't move a unit into the Tier-1 lane.
