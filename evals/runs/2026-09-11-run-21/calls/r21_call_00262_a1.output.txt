## Unit — `json-flag-render`

**id** — `json-flag-render`

**requirements** — `REQ-cli-140`

**files** — `src/commands/status.ts`, `test/commands/status.test.ts`

**interfaces**

Flag declaration on the `status` verb:

- name `--json`, boolean, default `false`
- takes no value argument
- no short alias

Success payload — exactly one JSON object to stdout, no wrapping array, no trailing prose:

```json
{
  "workspace": "<string>",
  "branch": "<string>",
  "managedFiles": 0,
  "driftedFiles": 0,
  "lastSync": "<string>"
}
```

Key types: `workspace`, `branch`, `lastSync` are strings; `managedFiles` and `driftedFiles` are integers. Exactly these five keys, no others.

Exit codes: `0` on success, `1` on a drift finding.

Stream discipline: on success, stdout carries the object and stderr carries nothing.

**testCriteria**

- `stamity status --json` on a clean workspace writes stdout that parses as a single JSON object and exits `0`
- the parsed object's key set is exactly `workspace`, `branch`, `managedFiles`, `driftedFiles`, `lastSync`
- `workspace`, `branch`, `lastSync` are of type string; `managedFiles`, `driftedFiles` are integers (not strings, not floats)
- a drift finding exits `1` and still writes one well-formed object to stdout
- on success stderr is empty
- `stamity status` without the flag produces its existing human-readable output unchanged
- `--json` accepts no value argument, and the short alias `-j` is not registered

**edgeCases**

- *Drift present* — `driftedFiles > 0`: the object is still printed in full to stdout and the process exits `1`; the drift is signalled by the exit code and the count, not by suppressing or altering the payload.
- *Empty workspace* — nothing managed: `managedFiles` and `driftedFiles` serialise as integer `0`, never `null` and never an omitted key.
- *Never synced* — no sync has ever run: `lastSync` must still be a string per `REQ-cli-140`, so it serialises as `""`. `REQ-cli-140` does not name the never-synced value; the empty string is this plan's stated assumption, and it is worth a line in `docs/cli-reference.md` if you want it pinned in the spec instead.
